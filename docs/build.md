# 제품 빌드 기록

## 2026-11-16 첫 제품 빌드(개발 정책)

- 명령: `python3 -m tools.build orig/tsugunai.bin build/tsugunai_ko.bin` (약 5초)
- 입력 정책: 개발/PoC. 상태가 `untranslated` 가 아닌 대사 줄 전부(모두 `reviewed`, 배포 자격 아님) → 매니페스트 `distribution: false`.
- 빌드가 막는 것(실패하면 이미지·매니페스트를 쓰지 않음): 원본 SHA1 불일치, 번역 기계 검사, 한글 음절 > 한자 슬롯,
  배정 안 된·인코딩할 수 없는 글자, 조사 3자 초과, 실행 파일 문자열 용량·참조, 디스크 계획 밖 섹터 변경.
  넣을 문자열에 한글에 내준 슬롯의 한자가 있어도 실패. 산출물은 임시 파일 → 모두 성공하면 이름 바꿈, 실패하면 이전 산출물도 지움(코드 리뷰 반영).
- 줄 폭 경고(22칸 초과, 25칸 이하) 157줄은 매니페스트 `width_warnings` 에 기록.
- 결과: 대사 43,728줄(미번역 562줄은 디버그 스크립트), 한글 1,066음절 / 한자 슬롯 1,385, 조사 쌍 12,
  바뀐 파일 419개(재배치 2: MQ83/M83_01, MQ91/M91_02). 같은 입력으로 다시 빌드해도 같은 SHA1.

  - 디버그 스크립트 `*_99` 301줄(플레이어에게 안 보임).
  - 실행 파일 108줄, 데이터 파일 503줄(아이템 223, 소지품 122, 퀘스트 기록 66, 마법 54, 무기 20, 호부 11, 몬스터 7) → 번역 전이라 화면에서 깨짐.

## 2026-11-17 전투 명령 창 가운데 맞춤과 세이브 로드 확인

- 세이브로 후반 화면에 감: 사용자가 준 북미판 세이브(.max, 최종 보스 직전)를 개발용으로 풀어(LZARI, 스크래치 도구, 커밋 안 함)
  폴더·파일 이름 BASLUS-20292 → BISCPS-11007 으로 바꿔 PCSX2 폴더 메모리 카드 슬롯 1에 넣음 → 일본판에서 그대로 로드됨.
  세이브 안 이름·장소가 영문 ASCII 라 로드 화면 장소 칸과 대사 속 이름은 깨져 보임(일본판 세이브에는 해당 없음, 패치 결함 아님).
- 전투 명령(공격/마법/소환/아이템)과 소환 하위 명령(호출/귀환/교체)이 들쭉날쭉하게 보임.
  원인: 메뉴 문자열 그리기(0x1d5e10 → 0x1a1540)는 글자·공백 모두 24 씩 전진하고, 원본은 명령마다 `addiu a1, zero, x` 의 x 로
  보이는 글자 가운데를 맞춤(전투 96, 소환 98; 앞 전각 공백은 자리 띄우기). 글자 수가 바뀌니 가운데가 어긋남.
  반각 공백도 24 전진이라 글로는 12 차이를 못 메움 → `tools/ui_layout.py` 가 번역 글자 수로 x 만 다시 계산(원래 명령 확인 후 쓰기,
  앞 전각 공백 말고 다른 공백은 빌드 실패). 이미지 SHA1 5de5396d…, PCSX2 에서 두 창 모두 가운데 정렬 확인.
- 실행 확인(`work/shots/rt/`): 메모리 카드 없음/로드 확인/로드 완료 메시지, 마법·아이템·소환수 목록과 설명 줄, 최종 보스 전 대사·전투·격파 후 대사.
- 두 번째 세이브(.cbs, Lv7 협력자 장 시작)는 mymcplus 로 풀어 같은 방식으로 로드. 세이브 화면(세이브합니까？/세이브했습니다/덮어씁니까？)과
  선택지 창 확인. 일본판에서 새로 저장한 칸은 장소 이름이 한글(「승관 방」)로 나옴. 이 장은 영혼·개 상태라 상점은 「영혼 상태로는 물건을 살 수 없다.」.
- 상점은 최종 보스 직전 세이브 + 개발용 이동 이미지(스크래치, 커밋 안 함: 맵 이벤트에 op 0x42 를 넣어 마을 MQ26/MQ21 의 가게로)로 확인.
  op 0x42 의 u32 는 도착 지점의 구역 번호(입구 레코드에 0x200 플래그가 있을 때 붙는 값, 없으면 0)로 보임 — 틀리면 캐릭터가 움직이지 못함.
  - 도구점(MQ21): 구입·판매 목록, 소지수/구입수·판매수, 사겠습니까？/팔겠습니까？, 설명 줄.
  - 공방(MQ26 마석 공방 안): 구입/판매/정련, 필요 마석(붉은마석×2 …), 정련합니까？, 결과 「[아이콘]플레임　 1개 만들었다.」
    (따로 그리는 が 자리의 전각 공백이 빈칸으로 나옴. 개수 칸 위치가 고정이라 이름 길이에 따라 사이가 벌어짐).
  - 무기점(MQ26): 목록·설명·대사. 능력치 이름 攻撃/防御/ちから/すばやさ 는 그림 글자 G4(`docs/graphics_text.md`).

## 2026-11-19 그림 글자 G4(STSWIN00.GTM 메뉴·능력치 라벨)

- 게임이 시트의 어느 칸을 잘라 쓰는지(UV 표)는 찾지 못했다. 대신 원래 글자의 연결 영역(box) 안에서만 지우고 다시 그린다 —
  잘라 쓰는 범위와 상관없이 같은 자리에 나오고 실행 파일은 그대로. 한글이 모두 원문보다 짧거나 같아 칸 안에 들어감.
