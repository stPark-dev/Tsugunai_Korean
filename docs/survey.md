## 확정 사항

### 파일 접근
- 게임은 `\FILEZ.DAT;1`을 자체 파일 테이블로 읽는다. 첫 u32 = 2486(ISO 파일 수와 일치).
  항목에 크기·LBA·디렉터리 번호·이름(구분자 없는 16바이트)이 들어 있다.
  예: `C00_01.MDL` → 크기 642346, LBA 16990 (ISO 디렉터리와 일치).
- 따라서 파일이 커지면 **FILEZ.DAT와 ISO 디렉터리 레코드를 함께 갱신**해야 한다.
  (FILEZ 항목 나머지 필드 의미와 게임 쪽 사용 여부는 미확정)

### SL00 압축 (45개 파일: FONT/*, MQ00 맵 모델 등)
- 해제 루틴 `0x19FCA0` (래퍼 `0x19FDF0`). 32비트 플래그 LZSS, 12비트 거리, 길이 3–273.
- 그룹 수 0이어도 첫 그룹 32항목은 무조건 처리 → 압축기는 32항목 미만을 만들지 않는다.
- `tools/sl00.py` 구현, 실제 FONT.BIN 해제 크기 일치·재압축 왕복 테스트 통과.

### 폰트 `DATAIMG/FONT/FONT.BIN` (SL00, 해제 510,032 B)
- +0x00..0x3F 미상(툴이 남긴 쓰레기값 포함), +0x40 u32 1, +0x44 폭 22, +0x45 높이 22, +0x46 u16 글자 수 2090
- +0x48 코드표 2090×u16 (Shift-JIS 값, 오름차순) → 이분 탐색 추정
- 이어서 글리프 2090×242 B (22×22, 4bpp, 하위 니블이 왼쪽 픽셀)
- 크기 합이 정확히 일치. 렌더링 확인: `work/font_sheet.png`
- 가나·기호 외 한자 약 1,450 슬롯. 코드표·글자 수가 파일 안에 있어 확장 가능성 있음(메모리 상한 미확인).
- 실행파일에 24폭·16폭 1bpp 행 전개 루틴(0x1A0C80, 0x1A0CF8)도 있음 → 다른 폰트 소비자 가능성(미확인)

### 스크립트 `DATAIMG/MQxx/SCP/*.SCP` (426개)
- 헤더 0x20 뒤 레코드 열: `u16 op, u16 len(헤더 포함)`, 4바이트 정렬, `FFFF FFFF` 구분자.
- op & 0x8000 = 컨테이너(자식 레코드가 +4부터). 자식 크기 변경 시 상위 len 전부 보정 필요.
- 텍스트는 평문 Shift-JIS, NUL 종료·4바이트 패딩. 인라인 제어 `01 xx`(색 등) 관찰.
- 텍스트 op(확정): `0x14` 장소명, `0x38` 화자, `0x39` 대사 줄, `0x3B` 선택지. `0x37` = 창 위치(x,y).
  다른 op에 보이는 SJIS(0xAC·0xB5 등)는 초기화 안 된 이름 버퍼 잔재 → 추출 대상 아님.
- 오프셋(확정): 헤더 u32×8, op 0x01 +4 u32(파일 내 절대 오프셋). 21,382건 전부 노드 시작/EOF를 가리킴.
- 0x8008 컨테이너 일부(M21_00, M24_01)는 실제 크기 > 64KB라 len 필드가 하위 16비트만 남음. 원본 그대로 재현.
